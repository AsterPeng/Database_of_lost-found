# 04 数据字典

## 1. 说明

- 类型为 PostgreSQL 实际类型；`timestamp(3)` 指 `TIMESTAMP(3) WITHOUT TIME ZONE`。
- “可空”列的 `NO` 表示 `NOT NULL`；`YES` 表示允许 `NULL`。
- “默认值”中的 `CURRENT_TIMESTAMP` 是数据库默认值；`updated_at` 由 Prisma 在应用层写入，没有数据库默认值。
- 主键、唯一键、外键、检查约束以 `db/sql/00_schema.sql` 为准；P2 计划新增的约束在 02 文档中列出，本字典只描述现状。
- 所有业务表主键为 `TEXT`，由应用生成 CUID；直接 SQL 插入必须提供 `id`。

## 2. 枚举类型字典

| 枚举 | 取值 | 含义 |
| --- | --- | --- |
| `Role` | `USER` / `ADMIN` | 普通学生 / 管理员 |
| `UserStatus` | `ACTIVE` / `BANNED` / `ARCHIVED` | 正常 / 被禁用 / 已归档 |
| `PostType` | `LOST` / `FOUND` | 寻物启事 / 拾物信息 |
| `PostStatus` | `OPEN` / `RESOLVED` / `CLOSED` | 寻找中 / 已解决 / 已关闭 |
| `MatchFeedback` | `NONE` / `MINE` / `NOT_MINE` / `UNSURE` | 未反馈 / 是我的 / 不是我的 / 待核实 |
| `TaskStatus` | `PENDING` / `DONE` / `FAILED` | 待处理 / 已完成 / 失败 |
| `ClaimStatus` | `PENDING` / `ACCEPTED` / `REJECTED` / `CANCELLED` | 待审核 / 已通过 / 已拒绝 / 已撤回 |
| `NotificationType` | `MATCH` / `CLAIM_RECEIVED` / `CLAIM_RESULT` / `CLAIM_ESCALATED` / `HANDOVER` / `SYSTEM` | 匹配推荐 / 收到认领 / 审核结果 / 认领超时 / 交接提醒 / 系统消息 |
| `ReportStatus` | `PENDING` / `RESOLVED` / `REJECTED` | 待处理 / 已处理 / 已驳回 |

## 5. 逻辑关联但无外键的字段汇总

| 字段 | 逻辑指向 | 现状 | 风险 |
| --- | --- | --- | --- |
| `claims.match_id` | `matches.id` | 无外键 | 匹配被删除后可能悬空；P2 补 `ON DELETE SET NULL` |
| `handovers.proposed_by_id` | `users.id` | 无外键 | 用户删除后可能悬空；P2 补 `ON DELETE SET NULL` |
| `handovers.completed_by_id` | `users.id` | 无外键 | 同上 |
| `audit_logs.target_id` | 由 `target_type` 决定 | 多态，无外键 | 目标删除后日志保留，属于审计需求，可接受 |
| `reports.target_id` | 由 `target_type` 决定 | 多态，无外键 | 目标删除后举报记录可能悬空；应用层处理 |

## 6. 字段命名与大小写提醒

- 大多数多词列使用 snake_case（如 `created_at`、`post_id`），由 Prisma `@map` 指定；
- `sessions."userAgent"` 是唯一未映射的驼峰列，SQL 中必须加双引号；
- 枚举类型名与值区分大小写（如 `PostStatus`、`'OPEN'`）；
- 表名全部小写复数（`users`、`posts`、`claims`）。
