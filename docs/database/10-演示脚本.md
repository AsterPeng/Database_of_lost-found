## 2. 10 分钟演示路线

### 0:00–1:00 打开增强展示页

打开 http://localhost:3001，说明：

- 页面仍是原来的失物招领应用；
- 数据库已完成课程化改造，但公开页面不需要改动即可运行；
- 首页展示原始演示帖子，说明展示库与测试库隔离。

### 1:00–2:00 展示数据库对象

```bash
psql "$DATABASE_URL" -c "select viewname from pg_views where schemaname='public' and viewname like 'v_%' order by 1;"
psql "$DATABASE_URL" -c "select matviewname from pg_matviews where schemaname='public' order by 1;"
psql "$DATABASE_URL" -c "select tgname from pg_trigger where not tgisinternal order by 1;"
psql "$DATABASE_URL" -c "select proname from pg_proc where pronamespace='public'::regnamespace and proname like 'fn_%' order by 1;"
```

讲解：

- 6 个视图把公开可见、认领详情、匹配总览等常用连接固定下来；
- 2 个物化视图保存院系/类别统计快照；
- 3 个触发器负责状态机、匹配一致性与审核审计；
- 4 个业务函数负责认领审核、超时转交、交接完成与统计。

### 2:00–3:30 统计下推与物化视图

```bash
psql "$DATABASE_URL" -c "select fn_stats(null::timestamptz, null::timestamptz, null::text);"
psql "$DATABASE_URL" -c "select * from mv_stats_department order by posts desc;"
psql "$DATABASE_URL" -c "select * from mv_stats_category order by posts desc;"
```

说明：

- 页面 `/admin/stats` 调用 `fn_stats`，页面与 CSV 共用同一口径；
- 全量总览可直接读物化视图，查询约 0.02 ms；
- 带时间/院系筛选的实时报表使用 `fn_stats`。

## 3. 常见提问

| 问题 | 回答要点 |
| --- | --- |
| 为什么不重写应用？ | 数据库课程重点是数据模型、约束、事务、安全与性能；原应用已验证业务流程，改造数据库层能更集中体现课程内容。 |
| 为什么认领审核放进数据库函数？ | 多步更新需要原子性；函数内用行锁和固定加锁顺序保证并发正确，应用层只负责通知与展示。 |
| 为什么物化视图和 fn_stats 并存？ | 全量总览适合快照；带时间/院系筛选的报表需要实时数据，用函数下推。 |
| 为什么 PostgreSQL 看不到脏读？ | PostgreSQL 将 READ UNCOMMITTED 视为 READ COMMITTED；MySQL InnoDB 的隔离级别行为不同，不能直接套用教材结论。 |
| 为什么表属主仍是 clfp？ | 保持 Prisma 迁移可用；RLS 只对演示角色生效，应用属主默认绕过，未使用 FORCE RLS。 |
| 为什么原项目库不动？ | 原项目与课程化增强版严格隔离，避免测试数据污染原展示；所有实验只在 clfp_enhanced / clfp_test / clfp_bench 进行。 |
