# 环境与端口说明

数据库课程化改造后，本项目同时运行三个**严格隔离**的实例。它们使用不同的代码目录、数据库和端口，互不影响。

## 1. 三个实例

| 端口 | 用途 | 代码目录 | 代码版本 | 数据库 | 启动命令 |
| --- | --- | --- | --- | --- | --- |
| **3000** | 原项目，冻结不改 | `D:\ClaudeCodeProjects\校园失物招领-original` | `b6e3ebb`（课程化改造前的基线） | `clfp_original` | `npm run dev` |
| **3001** | 数据库增强版展示 | `D:\ClaudeCodeProjects\校园失物招领` | `main` 最新提交 | `clfp_enhanced` | `npm run dev -- -p 3001` |
| **3002** | 回归测试专用 | `D:\ClaudeCodeProjects\校园失物招领-test` | `main` 最新提交（detached） | `clfp_test` | `npm run dev -- -p 3002` |

访问地址：

- 原项目：http://localhost:3000
- 增强版：http://localhost:3001
- 测试实例：http://localhost:3002（页面可打开，数据是测试数据，不要用于展示）

## 2. 数据库隔离

| 数据库 | 内容 | P2 对象 | 是否允许写测试数据 |
| --- | --- | --- | --- |
| `clfp_original` | 原始 3 个账号、1 条帖子「爱疯18Pro Max」、1 张图片、6 个类别 | 无 | **禁止** |
| `clfp_enhanced` | 与原始库相同的数据 | 6 视图、2 物化视图、3 触发器、函数与索引 | **禁止** |
| `clfp_test` | 只有种子账号与类别，E2E 会写入并清理测试数据 | 全部 P2 对象 | 允许 |

三个目录的 `.env` 分别指向自己的数据库，`.env` 不进版本库：

- `校园失物招领-original/.env` → `clfp_original`
- `校园失物招领/.env` → `clfp_enhanced`
- `校园失物招领-test/.env` → `clfp_test`

## 3. 测试规则

**不要对 3000 或 3001 运行 E2E。** 正确方式是从测试工作区对 3002 运行：

```bash
cd "D:\ClaudeCodeProjects\校园失物招领-test"
BASE_URL=http://127.0.0.1:3002 npm run verify:e2e
BASE_URL=http://127.0.0.1:3002 npm run verify:admin-claims
BASE_URL=http://127.0.0.1:3002 npm run verify:stats
```

`verify:m1` 不依赖 HTTP 服务，但也会写数据库；在测试工作区运行即可：

```bash
cd "D:\ClaudeCodeProjects\校园失物招领-test"
npm run verify:m1
```

每次在增强版目录提交新代码后，把测试工作区同步到最新提交：

```bash
git -C "D:\ClaudeCodeProjects\校园失物招领-test" checkout --detach main
```

## 4. 重置测试库

E2E 会在 `clfp_test` 留下部分测试数据，这是预期行为。需要干净环境时重置：

```bash
# 1. 停止 3002 服务
# 2. 重建数据库（连接参数来自 .env 中的 DATABASE_URL，去掉 ?schema=public）
psql "postgresql://.../postgres" -c "DROP DATABASE IF EXISTS clfp_test WITH (FORCE);"
psql "postgresql://.../postgres" -c "CREATE DATABASE clfp_test;"

# 3. 在测试工作区执行迁移与种子
cd "D:\ClaudeCodeProjects\校园失物招领-test"
DATABASE_URL="postgresql://.../clfp_test" npx prisma migrate deploy
DATABASE_URL="postgresql://.../clfp_test" npx tsx prisma/seed.ts
```

## 6. 为什么用三个目录

Next.js 16 的 Turbopack 不允许 `node_modules` 指向项目目录之外，也无法在同一个项目目录里同时运行两个 `next dev` 实例。因此：

- 原项目与测试实例使用 `git worktree` 从同一仓库检出到独立目录；
- 两个工作区各自复制了一份真实的 `node_modules`，不是软链接；
- 三个目录各自有独立的 `.next` 构建缓存和 `storage/uploads`。

原项目工作区固定检出在 `b6e3ebb`，后续所有课程化改造提交只影响 `main` 和增强版，不会改动 3000 的原项目代码。

## 7. 图片存储

- `校园失物招领-original/storage/uploads` 只放了原帖引用的 1 张图片；
- `校园失物招领/storage/uploads` 保留原项目图片，E2E 测试图片可能还在目录里，但增强库不引用它们；
- `校园失物招领-test/storage/uploads` 用于测试上传，可随时清空。

数据库只保存图片路径，恢复数据时如果图片文件缺失，页面会显示 404。原始图片已按 `post_images.path` 复制到对应目录。
