# 校园智能失物招领平台（CLFP）

基于 **RAG 语义匹配**的校园失物招领 Web 平台。学生发布丢失 / 拾获物品信息，系统用向量语义匹配把失主与拾主配对，并按置信度双向推荐。

> 需求来源：`docs/` 下的需求文档；范围与实现口径见 [PRD-web-v0.2.md](docs/PRD-web-v0.2.md)。

> **运行环境说明（数据库课程化改造后）**：3001 端口是增强展示版，3002 端口是测试实例。两个实例使用独立目录与独立数据库，回归测试只允许在 3002 执行。详见 [环境与端口说明.md](docs/database/环境与端口说明.md)。

## 技术栈

| 层 | 选择 |
| --- | --- |
| 前端 | Next.js 16（App Router）+ React 19 + TypeScript |
| 样式 | Tailwind CSS 4 |
| 后端 | Next.js Route Handlers / Server Actions |
| 数据库 | PostgreSQL 18 + Prisma 6 |
| 校验 | zod 4 |
| 密码与会话 | Node 内置 `crypto`（scrypt 哈希 + AES-256-GCM 字段加密），会话落库 |

> **注意**：`prisma` 与 `@prisma/client` 钉在 `6.19.3`。原因是 npm 上 `prisma` 的 `latest` 标签当前指向 `8.0.0-rc.19` 预发布版，与 `@prisma/client` 的 `7.10.0` 不匹配，直接安装会得到版本冲突的组合。

## M2 · 发布与管理（已完成）

- 发布寻物启事 / 拾物信息：标题、类别、地点、时间、特征描述（CLFP-USR-0003、0004）

- 删除为**软删除**（`deletedAt`），数据保留，配合后续管理员审核
- 我的发布列表，可按状态筛选（CLFP-USR-0018）
- 表单使用 React 19 的 form action：**禁用 JavaScript 也能提交**（此时不做图片压缩）

## M3 · 信息流与搜索（已完成）

- **公开信息流** `/posts`：按类型、类别、时间范围、地点、状态筛选（CLFP-USR-0006），分页每页 12 条
- **筛选条件全部写在 URL 里**，可以直接分享或收藏；「清除全部筛选」一键还原
- **关键词搜索** `/search`（CLFP-USR-0007）：
  - 查询串按空白拆成关键词，要求**每个关键词都命中**（AND 逻辑），每个关键词可命中标题、描述或地点之一
  - 相关度打分集中在 `scorePost()`：标题命中权重最高、地点次之、描述再次，完整查询串整体命中额外加分，越新的信息略微加分
  - 结果**分「寻物启事 / 拾物信息」两组**展示，每条显示相关度与命中位置
- **性能**：启用 PostgreSQL `pg_trgm` 扩展并建立 GIN 三元组索引，让 `ILIKE '%关键词%'` 也走索引
  （实测执行计划：`Bitmap Index Scan on posts_title_trgm_idx`）
- 首页展示最新寻物 / 拾物各 4 条与搜索入口

## M4 · RAG 语义匹配（已完成）

**流程（CLFP-USR-0008、0020）**：发布或编辑帖子 → 写入 `embedding_tasks` 任务 → 生成向量存入 `post_embeddings` → 与类型互补的历史帖子比对 → 超过阈值的配对写入 `matches`（双向可见）。

**可插拔模型层（CLFP-USR-0025）**，`src/lib/rag/`：

| 文件 | 职责 |
| --- | --- |
| `types.ts` | `EmbeddingProvider` / `ChatProvider` 统一接口 |
| `providers.ts` | mock（本地特征哈希）、OpenAI 兼容（OpenAI / 火山方舟等）、Ollama |
| `config.ts` | 权重、阈值、时间窗等配置，存放在 `app_configs` 表，可在后台调整 |
| `matching.ts` | 打分明细、匹配生成、推荐理由、反馈驱动的权重自适应 |
| `pipeline.ts` | 任务入队与处理流水线 |

**降级模式（默认）**：不配置任何 API Key 时使用本地特征哈希向量（中文按字符二元组做特征哈希并 L2 归一化），关键词、类别、地点、时间维度照常参与打分，因此没有 Key 也能完整演示。配置了真实模型后自动切换；**远程调用失败会自动回退到本地实现并记录原因，不会让发布失败**。

**置信度公式**（权重来自配置表）：

```
置信度 = (0.50×向量相似度 + 0.15×类别匹配 + 0.15×地点匹配 + 0.10×时间接近度 + 0.10×关键词重合) × 类别权重系数
```

- 结构化预过滤：只比较类型互补、状态正常、作者不同、发生时间在 30 天窗口内的帖子
- 阈值 0.45、每条帖子最多推荐 5 条，均可配置
- **推荐理由**：默认由规则生成（类别一致 / 地点相同 / 时间接近 / 描述相似…），配置了对话模型时改由模型生成，并严格限制只能基于给定两条信息、失败自动回退规则文案

**「我的匹配」** `/me/matches`（CLFP-USR-0009）：展示对方信息摘要、置信度、推荐时间、类别、推荐理由，并可展开查看打分明细。

**反馈机制**（CLFP-USR-0010）：`是我的物品 / 不是我的物品 / 待核实`

- 选「不是我的物品」后该配对立即从双方列表消失，并且不再被重复推荐
- 所有反馈参与类别权重自适应：某类别正反馈比例越高，该类别的匹配置信度越高（系数范围 0.5~1.5，样本少于 3 条时不调整，避免被个别反馈带偏）

**worker**：

```bash
npm run worker              # 常驻，轮询处理待办向量化任务
npm run worker -- --once    # 处理完当前积压后退出
npm run rag:rebuild         # 全部帖子重新向量化并重算匹配（换模型后使用）
```

> 发布时会同步执行一次流水线，保证不启动 worker 也能立即看到匹配结果；worker 用于批量补算与换模型后的重建。

## M5 · 认领与交接（已完成）

**认领流程（CLFP-USR-0011）**

1. 在信息详情页点「我要认领」（不能认领自己发布的信息，信息已结束也不能认领）
2. 填写**认领说明 + 认领凭证 + 联系方式**，凭证要求填写只有真正主人才知道的细节
3. 申请进入待处理状态，同时记录一个 **48 小时后自动转交管理员**的时限
4. 帖子作者审核：**通过**或**拒绝**（可附备注）
5. 通过后的连带效果：该信息自动标记为**已解决**、同一帖子的其它待审申请自动拒绝、自动创建交接记录
6. 作者 48 小时未处理 → 页面加载时**自动标记为「已转交管理员」**（懒执行，不需要额外的定时任务），管理员在 `/admin/claims` 待办中处理
7. 申请人可以**撤回**申请；被拒绝或撤回后可以补充信息重新申请

**联系方式保护（CLFP-USR-0014）**

- 认领时填写的联系方式**字段级加密**入库，页面只展示脱敏值（`139****5678`、`wx****23`）
- **互相授权**才可见：认领通过后，双方各自决定是否「向对方展示我的联系方式」；只有对方授权后，你才能看到完整值，并可随时撤回
- 权限判断在服务端完成，未授权时接口层根本不返回完整联系方式

**线下交接（CLFP-USR-0012）**

- 认领通过后开启交接：任一方提交**交接时间与地点**，双方都能看到当前安排以及由谁提议
- 完成交接后任一方点「确认交接完成」即生效（已确认的口径），系统记录完成时间与确认人

**页面**：`/posts/[id]/claim` 发起认领、`/me/claims` 我的认领（发起 + 收到）、`/me/claims/[id]` 当事人详情（审核、交接、联系方式授权）、`/admin/claims` 管理员待办与记录、`/admin/claims/[id]` 管理员审核详情

## M6 · 站内通知与消息偏好（已完成）

Web 版用**通知中心**替代微信订阅消息（见 PRD 第 1 节的能力替换说明）。

**触发点（CLFP-USR-0013）**

| 类型 | 触发时机 | 接收人 |
| --- | --- | --- |
| 匹配推荐 MATCH | 发布/编辑后产生新匹配 | 双方作者各收到一条 |
| 收到认领 CLAIM_RECEIVED | 有人提交认领申请 | 信息发布者 |
| 审核结果 CLAIM_RESULT | 认领被通过或拒绝 | 申请人；通过时同帖其它申请人也会收到 |
| 认领超时 CLAIM_ESCALATED | 48 小时未处理自动转交 | 全部管理员 |
| 交接提醒 HANDOVER | 对方提交交接安排、或确认交接完成 | 另一方 |
| 系统消息 SYSTEM | 预留（公告、下架通知等） | — |

**免打扰时段（CLFP-USR-0019）**

- 默认 22:00–次日 07:00，可在账号设置里开关与调整起止小时，支持跨天
- 时段内产生的通知**不会立即送达**：写入时把 `deliverAt` 推迟到时段结束的整点
- 通知中心只展示已到送达时间的通知；对未到时间的只显示「有 N 条通知处于免打扰时段，已为你暂缓发送」
- 送达时间由纯函数 `computeDeliverAt()` 计算，单元测试覆盖跨天、同日、关闭开关、起止相同等边界
- 关闭「接收站内通知」后不再写入任何通知记录（偏好保留，随时可恢复）

**通知中心** `/me/notifications`：类型标签、已读/未读、跳转链接、单条标记已读与全部标记已读；导航栏显示未读角标。

## M7 · 管理后台（已完成）

入口 `/admin`，非管理员访问会被直接跳走（`requireAdmin()`）。

| 页面 | 能力 | 对应需求 |
| --- | --- | --- |
| `/admin` | 用户数、信息数、匹配数、待处理认领、已下架、24 小时新增、找回率、当前匹配配置、最近操作 | 0017（加分项） |
| `/admin/posts` | 按状态（全部/寻找中/已解决/已下架/已删除）与标题搜索；**下架**（需填原因）、**恢复展示**、**删除** | 0016 |
| `/admin/claims` | 只将超时转交且仍待审的申请列入待办；可查看全部记录，并在专用详情页核对凭证、通过或拒绝，审核写入操作日志 | 0011 |
| `/admin/logs` | 最近 100 条管理操作：时间、操作人、动作、对象、详情 | 0016 |
| `/admin/config` | 调整匹配阈值、最多推荐数、时间窗与五项权重；新增/停用物品类别；模型接入说明 | 0025 |

**下架与删除的区别**（对应需求里「下架或删除」的两种处置）：

- **下架**：`takenDownAt` 标记，可恢复。下架后不进入公开列表、搜索与匹配候选，其他人访问详情返回 404；**作者与管理员仍可见**，作者会收到系统通知并被告知原因
- **删除**：软删除，作者无法自行恢复，用于违规内容

**先发后审**：发布立即可见，管理员通过 `/admin/posts` 事后审核处置（这是已确认的口径）。

**操作日志**：所有管理动作（下架/恢复/删除/类别变更/配置变更）都写入 `audit_logs`，记录操作人、对象与上下文；日志只增不改。认领审核也会记录审核人角色（作者或管理员）。

## 课堂演示建议路线

1. **注册与登录**：注册一个账号 → 自动进入「完善校内资料」→ 账号设置里看「通知偏好」
2. **发布**：发布一条寻物启事（上传 2~3 张图，会看到自动压缩）→ 发布一条高度相似的拾物信息（换一个账号）
3. **RAG 匹配**：发布后立刻进「我的匹配」，看到**置信度、推荐理由**，展开「打分明细」解释分数怎么来的
4. **反馈**：点「不是我的物品」→ 该配对消失；连续给几条「是我的物品」→ 配置中心/匹配页出现**类别权重自适应**提示
5. **认领闭环**：切换账号提交认领（填凭证）→ 回到发布者账号审核通过 → 信息自动变「已解决」→ 约定交接时间地点 → 确认交接完成
6. **隐私**：认领通过前双方只看到 `139****5678`；各自点「向对方展示我的联系方式」后才互相可见
7. **通知**：看导航栏未读角标 → 通知中心；在设置里把免打扰时段设为覆盖当前小时，再触发一条通知，会看到「已为你暂缓发送」
8. **管理后台**：用 `admin@clfp.local` 登录 → 信息管理里**下架**一条信息（普通用户视角立刻 404，作者仍能看到并收到通知）→ 举报处理 → 发布公告看首页 → 统计报表导出 CSV → 操作日志复盘刚才所有动作

## 部署与运维

**生产构建**

```bash
npm ci
npx prisma migrate deploy     # 只应用迁移，不改结构
npm run build
npm run start                 # 默认 3000 端口
npm run worker                # 另起一个进程跑向量化任务（可选）
```

**必须注意的三件事**

1. **`.env` 里的 `ENCRYPTION_KEY` 一旦更换，已加密的手机号与认领联系方式将无法解密**，务必备份
2. 上传的图片在 `storage/uploads/`，**不在数据库里**，备份要连目录一起备（或改用对象存储，只需改 `src/lib/storage.ts`）
3. 生产环境必须在反向代理上启用 HTTPS（小程序要求，Web 版同样是安全要求），并把 `NODE_ENV=production`，此时会话 Cookie 会自动带上 `Secure`

**数据库备份**

```bash
pg_dump -U clfp -h 127.0.0.1 clfp_dev > backups/clfp_$(date +%F).sql
```

**换向量模型后**

```bash
npm run rag:rebuild           # 全量重建向量并重算匹配
```

## 常见问题

**`prisma generate` 报 `EPERM: operation not permitted, rename ...query_engine-windows.dll.node`**
开发服务器正在运行时会锁住 Prisma 的引擎文件。先停掉 `npm run dev` 再执行 `npx prisma generate`，然后重新启动开发服务器。
注意：改了 `schema.prisma` 后如果没重新生成客户端，运行时会报 `Cannot read properties of undefined (reading 'findFirst')` 这类错误——它是"客户端是旧的"，不是数据问题。

**`npm run dev` 报 `spawn EPERM`**
说明命令运行在受限沙箱里。Next.js、Prisma、esbuild 都需要创建子进程，受限模式不允许。把 DSH 会话切到「完全权限」后即可正常运行。

**数据库连不上**
确认 PostgreSQL 服务在运行，且 `.env` 里的 `DATABASE_URL` 账号密码正确。迁移需要该账号有 `CREATEDB` 权限：

```sql
ALTER ROLE clfp CREATEDB;
```
